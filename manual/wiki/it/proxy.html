Proxy e catene

Visual Chain Builder, rotazione, mappa ACTIVE CHAIN e chain multi-protocollo — il sottosistema proxy unificato di Anibus 2.2.0.

Panoramica

Servizio ProxyChainService + pannello Proxy nella finestra principale. Tutte le richieste HTTP di Anibus, eccetto le probe loopback esplicite, passano attraverso la catena impostata. Tipo di ciascun nodo:

  • HTTP / HTTPS — tunnel CONNECT standard.
  • SOCKS4 / SOCKS5 — supportata l'autenticazione username/password.
  • TOR — tramite la porta SOCKS5 locale del demone TOR.

Visual Proxy Chain Manager NEW

Il pulsante Build Chain apre un dialogo con editor drag-and-drop:

  1. A sinistra — pool dei nodi (importati da file o inseriti manualmente).
  2. Al centro — la catena sequenziale. I nodi si possono trascinare, riordinare, eliminare.
  3. A destra — parametri del nodo selezionato: host, port, username, password, tipo.
  4. Il pulsante Test Chain avvia una probe sulla catena (HEAD su URL di test).

Dopo l'applicazione la catena viene visualizzata nella card ACTIVE CHAIN della scheda Proxy:

ACTIVE CHAIN
[HTTPS] corp-gw.local:8443  →  [SOCKS5] tor-bridge:9050  →  TARGET

Rotazione e modalità chain

  • Strict chain — tutti i nodi sono usati nell'ordine indicato.
  • Round-robin — ogni richiesta passa attraverso il nodo successivo della catena.
  • Random — nodo casuale a ogni richiesta.
  • Fallback — primo nodo funzionante in caso di errore su quello a monte.

Dialogo localizzato

I testi del Proxy Chain Builder sono localizzati in EN/IT/RU. Tutte le chiavi sono convalidate da ResourceBundleValidationTest — aggiungere una nuova stringa richiede tre traduzioni in contemporanea.

Profili di timeout

HttpClientFactory.TimeoutProfile:

ProfiloConnect / ReadDove si applica
FAST2 / 2 sProbe massive di porte, favicon
NORMAL5 / 5 sProbe HTTP standard
SLOW10 / 10 sServizi auth, IdP
VERY_SLOW20–30 sOAuth token endpoint, RDAP, AXFR

I profili vengono passati come secondo argomento in HttpClientFactory.open(url, profile). Tutte le chiamate di questa facade attraversano la catena proxy.

Politica di retry

Backoff esponenziale + jitter per errori di rete transitori (timeout, reset, 5xx). Configurabile in Config → Network → Retry:

  • Max attempts (default 3).
  • Base delay (250 ms) con esponente 2.
  • Jitter ±25% per distribuire il carico.

Trust-all SSL

InsecureSsl — utility unificata trust-all SSLSocketFactory + hostname verifier. Usata dai detector che devono lavorare con certificati self-signed (KeycloakDetector, IdentityProviderDetector, SqlMetadataExtractor). Si applica solo all'interno dello scanner e non sostituisce il TrustManager globale della JVM.

Sicurezza Più lunga è la catena, maggiori sono latenza e punti di failure. Per operazioni critiche (Build Chain → Test Chain) usa 2–3 nodi.
