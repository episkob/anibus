Scansioni di base

Scansione TCP/UDP standard, service detection, modalità batch e IPv6 — il fondamento di qualsiasi sessione di pentest in Anibus.

Campo Target

Il campo accetta:

  • IPv4: 192.168.1.10, range 192.168.1.0/24.
  • IPv6: fe80::1 oppure [::1] (le parentesi vengono rimosse automaticamente).
  • Hostname: example.com (risolto tramite HostResolver, supporto a più A/AAAA).
  • URL: https://example.com/app/ — usato come baseUrl per le scansioni web.

Range di porte

Nel campo Ports si accettano:

  • Porta singola: 443 (single-port mode aggiunto in 2.2.0).
  • Range: 1-1024.
  • Elenco: 22,80,443,8080-8090.
  • Preset: «Top 100», «Web», «DB», «Mail» — selezionabili dal menu a tendina.

Standard Scan

Il pulsante Scan avvia una scansione TCP standard tramite StandardScanStrategy + ScanCoordinator. Per ogni porta viene allocato un virtual thread, il che permette di lavorare con range di migliaia di porte senza bloccare la UI.

[12:34:01] [INFO]  Scan started: 192.168.1.10 (1-1024)
[12:34:02] [OPEN]  22/tcp   SSH       OpenSSH 9.6p1
[12:34:02] [OPEN]  80/tcp   HTTP      nginx/1.25.3
[12:34:03] [OPEN]  443/tcp  HTTPS     nginx/1.25.3
[12:34:05] [INFO]  Scan finished in 4.2s · 3 open / 1021 closed

Service Detection

Su ogni porta trovata viene avviato ServiceDetectionTask: HTTP HEAD, TLS handshake, banner del raw socket. I risultati vengono scritti nelle righe OPEN e diventano l'input per gli scanner CVE/Vulnerability/JS.

UDP Scan

Il pulsante udpScanButton avvia UdpScannerService: invio di probe protocollo-dipendenti (DNS query, SNMP get-request, NTP request, NetBIOS name query). La risposta o l'ICMP unreachable determina lo stato della porta.

Quota ICMP La maggior parte dei SO limita gli ICMP unreachable — le scansioni UDP estese risultano più lente del TCP. Usa elenchi brevi di porte (DNS/SNMP/NTP/NetBIOS).

Scansione IPv6

In 2.2.0 HostResolver supporta IPv6: rimozione delle parentesi quadre [fe80::1], fallback IDN. Se l'host ha sia A che AAAA, è possibile scegliere la famiglia preferita in Config → Network.

Batch / Multi-target

Il menu Discovery → Batch Scan apre BatchScanService: in input un file di testo o un elenco di target incollato. La scansione viene eseguita in sequenza con un report aggregato e un'intestazione comune in Scan Results.

192.168.1.0/24
example.com
fe80::1%eth0
https://app.internal/

Diff Mode

Il pulsante diffModeButton avvia ScanDiffService: confronto di due scansioni salvate in ~/.anibus/history/. Vengono mostrate:

  • NEW — nuove porte aperte / nuove scoperte.
  • CHANGED — variazioni di banner/versione.
  • GONE — servizi scomparsi.

Menu contestuale di Scan Results

Tasto destro su una riga di risultato:

  • Salva nella cronologia — il risultato attuale viene aggiunto a ScanHistoryService.
  • Confronta con… — apre il wizard di diff.
  • SQL Metadata Extraction — avvia SqlMetadataExtractor per i find SQLi.
  • Copy as curl — copia uno snippet curl (da EndpointInfo).
  • Apri PoC URL — per i risultati XSS/SSRF con pocCurl().

Ricerca nella console

Ctrl+F apre il filtro inline di Scan Results. Ricerca in realtime, case-insensitive. Per altre combinazioni di tasti vedi Hotkeys.
