Глава 1. Первый запуск и быстрый старт

Учебные цели
  • Собрать первую стабильную конфигурацию сканирования.
  • Понять баланс скорости и точности через THREADS/PORT RANGE.
  • Сформировать baseline-отчет для сравнения в будущем.
  1. Откройте Anibus и проверьте состояние Ready.
  2. Введите TARGET: hostname, IP или URL.
  3. Укажите PORT RANGE и THREADS.
  4. При необходимости включите JavaScript Analysis и SQL Injection Testing.
  5. Нажмите Start Scan.
Практическое задание

Выполните два прогона (20 и 60 потоков), затем сравните шум логов, полноту находок и стабильность соединения.

Глава 6. Proxy, Chain Builder и Transport

Кейс: Стабилизация proxy-маршрутов

До

Частые timeout и нестабильные результаты в сложных сетевых условиях.

Типовые ошибки

  • Завышенный THREADS на слабом пуле.
  • Отсутствие fallback-цепочки.
  • Игнорирование карантина маршрутов.

Разбор решения

Стабильный селектор, валидированный transport и ротация по failure streak повышают качество результатов.

Глава 15. Руководство администратора (развертывание, профили, hardening)

15.1 Модель развертывания

Развертывайте Anibus на контролируемых рабочих станциях аналитиков, изолированных от production-админских сессий.

15.2 Профили эксплуатации

ПрофильЦельРекомендуемые настройки
DevБыстрая итерацияУзкий диапазон, средние потоки, подробные логи
StageПредпрод проверкаСредний диапазон, строгая дисциплина экспорта
Prod AuditКонтролируемый аудитКонсервативные потоки, плановые окна

15.3 Hardening checklist

  • Запуск под least-privilege учетной записью.
  • Контроль outbound маршрутов и egress-политик.
  • Защита каталогов history/report и артефактов экспорта.
  • Регламент хранения результатов и журналов.
  • Версионирование профилей и формальные approval-процедуры.

15.4 Proxy hardening policy

  • Предпочтение стабильному селектору и проверенному пулу.
  • Карантин проблемных направлений и ротация цепочек.
  • Периодическая ревалидация cache-пула.

15.5 Операционная дисциплина

Разделите роли оператор/ревьюер/аппрувер, фиксируйте scope и сохраняйте артефакты в неизменяемом хранилище.

Кейс: Потеря трассируемости аудита

До

Нельзя надежно установить, кто запускал проверку и по какому scope.

Типовые ошибки

  • Общие учетные записи операторов.
  • Отчеты без привязки к заявке.
  • Хранение без неизменяемой retention-политики.

Разбор решения

Разделение ролей, ticket-трассировка и архив с защитой от правок закрыли audit gap.

Глава 16. Cookbook (готовые playbook-сценарии)

Методика выполнения

Запускайте сценарии строго по шагам и меняйте за итерацию только один параметр. Это делает результаты воспроизводимыми.

Playbook 1: Быстрая карта внешней поверхности

  1. Диапазон 1-4096, потоки 20-40.
  2. Скан + WHOIS + TLS + HTTP protocol detect.
  3. Экспорт baseline-отчета.

Playbook 2: Web risk snapshot

  1. Включить JS Analysis и SQL Testing.
  2. Запустить XSS/CORS/JWT/GraphQL набор.
  3. Сортировать по confidence/priority и экспортировать.

Playbook 3: Устойчивый proxy режим

  1. Load from file + Start Harvesting refresh.
  2. Transport Auto и проверка логов endpoint availability.
  3. Rotate/failover на сбоях, обновление цепочки.

Playbook 4: Плановый drift monitoring

  1. Включить scheduler в допустимое окно.
  2. Сравнивать snapshots через Diff Mode.
  3. Эскалировать только устойчивые изменения.

Playbook 5: Incident triage support

  1. Сузить scope до incident perimeter.
  2. Провести быстрый пакет проверок.
  3. Сформировать короткий отчет для SOC handoff.
Кейс: Ускорение инцидент-триажа

До

На каждое событие запускались полные проверки, что тормозило реакцию команды.

Типовые ошибки

  • Нет первичного сужения периметра.
  • Смешивание baseline и incident данных.
  • Неформализованный handoff в SOC.

Разбор решения

Сценарий с узким scope, сравнением snapshots и коротким отчетом ускоряет handoff без потери точности.

Глава 17. Полный каталог реализованных функций (по TODO + коду)

17.1 Архитектура и качество

  • DI wiring через приложение, unit/integration тесты, checkstyle pipeline.
  • Практика: перед релизом прогон compile/test и smoke-сценариев вручную.

17.2 Подключенные действия Scan Results

  • UDP Scan, Subdomain, SourceMap, Param Miner, Diff Mode, Scheduler start/stop.
  • Практика: после базового скана запускайте модули кнопками в этой же вкладке.

17.3 Анализ и обнаружение

  • Passive Recon, secrets validation, auth crawling, API Security Mode.
  • Confidence/risk scoring + curl snippets в JS Analysis.
  • XSS/SSRF/XXE/CORS/JWT/GraphQL/takeover проверки.
  • SourceMap Exploit Context и SQL-to-DB extraction.

17.4 Сеть и инфраструктура

  • Drift scheduler, topology map, WHOIS, TLS audit, DNS AXFR.
  • HTTP/2-3, WebSocket detector, ASN lookup, IPv6 support.

17.5 Уязвимости и CVE

  • CVE severity группировка и Exploit-DB ссылки.
  • Log4Shell, Spring4Shell, Heartbleed, расширенные fingerprint checks.

17.6 UI и экспорт

  • Proxy Chain Visual Manager, HTML/PDF экспорт, Statistics dashboard.
  • История сканов с compare, live filter, hotkeys, notifications, theme switcher.
