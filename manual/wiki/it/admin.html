Amministrazione e risoluzione dei problemi

Hotkey, temi, dizionari, checklist di hardening, errori tipici e limiti legali di utilizzo di Anibus.

Temi

Menu Config → Tema:

  • Scuro (predefinito) — Bootstrap 5 Dark con CSS personalizzato.
  • Chiaro — override anibus-style-light.css, commutazione tramite RadioMenuItem.

Dizionari

File sotto ~/.anibus/wordlists/:

  • subdomains.txt — per SubdomainEnumerationService.
  • sqli-payloads.txt — per SQL Injection Analyzer (se non si usa il profilo CMS integrato).
  • endpoints.txt — per ParamMiner / Directory Bruteforce.

Lo stato dei dizionari attivi è mostrato nella UI di Scan Target.

Configurazione

Le impostazioni utente sono conservate in ~/.anibus/config.properties:

theme=dark
locale=ru
default.timeout.profile=NORMAL
proxy.chain.policy=strict
scheduler.enabled=true
cve.cache.refresh.hours=24

Checklist di hardening

  1. Avvia Anibus in un segmento di rete isolato (VLAN di test).
  2. Usa un account utente dedicato senza sudo, eccetto per le scansioni UDP.
  3. Abilita la catena proxy per tutte le scansioni esterne — nessuna richiesta diretta.
  4. Pulisci ~/.anibus/history/ secondo policy (i log CRITICAL contengono potenziali segreti).
  5. Aggiorna regolarmente la CVE Offline DB tramite lo Scheduler.
  6. Non avviare mai Anibus con certificati radice fidati nel TrustStore di sistema — InsecureSsl è usato solo all'interno dei detector.

Troubleshooting

JavaFX non si avvia

Verifica JDK 21 e la presenza di javafx-controls/fxml/graphics/base nel classpath:

./mvnw -B -Pjavafx javafx:run

Su Wayland con finestra vuota prova GDK_BACKEND=x11 ./mvnw ….

Timeout HTTP su target lenti

Config → Network → Default Timeout Profile → SLOW o VERY_SLOW.

L'autenticazione NTLM non funziona

  • Verifica che il dominio sia indicato nel formato DOMAIN\\user e non come UPN.
  • Controlla la versione: NTLMv1 non è supportato, solo NTLMv2.
  • Log: Discovery → Auth Crawl → Show Wire Trace.

La catena proxy fallisce

  • In Build Chain → Test Chain: osserva quale nodo è caduto.
  • Catene SOCKS lunghe richiedono il profilo SLOW.
  • Per TOR verifica che il demone sia in ascolto sulla 9050.

Cache CVE vuota

  • Controlla l'accesso di rete a services.nvd.nist.gov (tramite chain se necessario).
  • Avvia l'aggiornamento manuale: Scheduler → Update CVE DB now.
  • Per ambienti air-gapped — copia ~/.anibus/cve-cache/ da una macchina connessa.

I test falliscono

./mvnw -B test
./mvnw -B test -Dtest=SQLInjectionAnalyzerTest

Se fallisce ArchUnit significa che sono violati i confini modulari (service→handler, util→handler, coordinator→JavaFX, model→coordinator).

Log

File target/classes/logging.properties + console runtime con timestamp realtime. Livelli: INFO / WARN / ERROR / DEBUG. Il livello si modifica tramite Config → Logging.

Graceful shutdown

shutdownExecutor() invoca schedulerService.shutdown() e isola gli errori di ciascun servizio tramite shutdownSafe(). I pool daemon nominati (NamedThreadFactory.of()) — network-monitor, scan-scheduler — terminano correttamente alla chiusura della finestra.

Limiti legali

Solo utilizzo autorizzato Anibus esegue probe attive (XSS, SSRF, SQLi, Heartbleed, operazioni ausiliarie di brute NTLMv2). Queste azioni nella maggior parte delle giurisdizioni richiedono un'autorizzazione scritta del proprietario della risorsa.
  • Usalo solo sulla tua infrastruttura o con rules-of-engagement firmate.
  • Per i bug bounty pubblici verifica lo scope del programma specifico.
  • Non avviarlo mai su un target senza consenso — è penalmente perseguibile in Russia (CP 272/273), nell'UE (Computer Misuse Act / Direttiva 2013/40) e negli USA (CFAA).
