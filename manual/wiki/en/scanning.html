Basic scans

Standard TCP/UDP scanning, service detection, batch mode and IPv6 — the foundation of every pentest session in Anibus.

Target field

The field accepts:

  • IPv4: 192.168.1.10, ranges 192.168.1.0/24.
  • IPv6: fe80::1 or [::1] (brackets are stripped automatically).
  • Hostname: example.com (resolved through HostResolver, multiple A/AAAA records supported).
  • URL: https://example.com/app/ — used as the baseUrl for web scans.

Port ranges

The Ports field accepts:

  • A single port: 443 (single-port mode added in 2.2.0).
  • A range: 1-1024.
  • A list: 22,80,443,8080-8090.
  • Presets: "Top 100", "Web", "DB", "Mail" — picked from the dropdown.

Standard Scan

The Scan button runs a standard TCP scan via StandardScanStrategy + ScanCoordinator. Each port gets its own virtual thread, allowing ranges of thousands of ports without blocking the UI.

[12:34:01] [INFO]  Scan started: 192.168.1.10 (1-1024)
[12:34:02] [OPEN]  22/tcp   SSH       OpenSSH 9.6p1
[12:34:02] [OPEN]  80/tcp   HTTP      nginx/1.25.3
[12:34:03] [OPEN]  443/tcp  HTTPS     nginx/1.25.3
[12:34:05] [INFO]  Scan finished in 4.2s · 3 open / 1021 closed

Service Detection

For each open port a ServiceDetectionTask is launched: HTTP HEAD, TLS handshake, raw-socket banner grab. The results feed the OPEN lines and serve as input for the CVE / Vulnerability / JS scanners.

UDP Scan

The udpScanButton button starts UdpScannerService: it sends protocol-aware probes (DNS query, SNMP get-request, NTP request, NetBIOS name query). The response — or an ICMP-unreachable — determines port state.

ICMP quota Most operating systems throttle ICMP-unreachable, so large UDP scans run slower than TCP. Use short port lists (DNS/SNMP/NTP/NetBIOS).

IPv6 Scan

In 2.2.0, HostResolver supports IPv6: unwrapping of [fe80::1], IDN fallback. If a host has both A and AAAA records, you can pick the preferred family in Config → Network.

Batch / Multi-target

The Discovery → Batch Scan menu opens BatchScanService: input is a text file or a pasted target list. Scans run sequentially with an aggregated report and a single header in Scan Results.

192.168.1.0/24
example.com
fe80::1%eth0
https://app.internal/

Diff Mode

The diffModeButton button runs ScanDiffService: it compares two saved scans from ~/.anibus/history/. It shows:

  • NEW — newly opened ports / findings.
  • CHANGED — banner or version changes.
  • GONE — services that disappeared.

Scan Results context menu

Right-click on a result row:

  • Save to history — the current result is added to ScanHistoryService.
  • Compare with… — opens the diff wizard.
  • SQL Metadata Extraction — runs SqlMetadataExtractor against an SQLi finding.
  • Copy as curl — copies a curl snippet (from EndpointInfo).
  • Open PoC URL — for XSS / SSRF results that expose pocCurl().

Console search

Ctrl+F opens the inline Scan Results filter. Search is realtime and case-insensitive. See the rest of the bindings in Hotkeys.
