Proxy & chains

Visual Chain Builder, rotation, ACTIVE CHAIN card and multi-protocol chains — the unified proxy subsystem of Anibus 2.2.0.

Overview

The ProxyChainService + the Proxy pane in the main window. All Anibus HTTP requests except explicit loopback probes go through the active chain. Node types:

  • HTTP / HTTPS — standard CONNECT tunnel.
  • SOCKS4 / SOCKS5 — supports username/password authentication.
  • TOR — through the local SOCKS5 port of the TOR daemon.

Visual Proxy Chain Manager NEW

The Build Chain button opens a dialog with a drag-and-drop editor:

  1. Left — pool of nodes (imported from a file or entered manually).
  2. Centre — the sequential chain. Nodes can be dragged, reordered, removed.
  3. Right — parameters for the selected node: host, port, username, password, type.
  4. The Test Chain button runs a chain probe (HEAD on a test URL).

Once applied, the chain shows up on the ACTIVE CHAIN card in the Proxy tab:

ACTIVE CHAIN
[HTTPS] corp-gw.local:8443  →  [SOCKS5] tor-bridge:9050  →  TARGET

Rotation and chain modes

  • Strict chain — every node is used in the specified order.
  • Round-robin — each request goes through the next node in the chain.
  • Random — a random node per request.
  • Fallback — the first working node when an upstream one fails.

Localized dialog

The Proxy Chain Builder strings are localized into EN/IT/RU. All keys are validated by ResourceBundleValidationTest — adding a new string requires all three translations at once.

Timeout profiles

HttpClientFactory.TimeoutProfile:

ProfileConnect / ReadWhere used
FAST2 / 2 sMassive port probes, favicon
NORMAL5 / 5 sStandard HTTP probe
SLOW10 / 10 sAuth services, IdP
VERY_SLOW20–30 sOAuth token endpoint, RDAP, AXFR

Profiles are passed as the second argument to HttpClientFactory.open(url, profile). All calls through this facade run through the proxy chain.

Retry policy

Exponential backoff + jitter for transient network errors (timeout, reset, 5xx). Configurable in Config → Network → Retry:

  • Max attempts (3 by default).
  • Base delay (250 ms) with exponent 2.
  • Jitter ±25% to smear the load.

Trust-all SSL

InsecureSsl — a single trust-all SSLSocketFactory + hostname-verifier utility. Used by detectors that must talk to self-signed certificates (KeycloakDetector, IdentityProviderDetector, SqlMetadataExtractor). Applied strictly inside the scanner; it does not override the global JVM TrustManager.

Security The longer the chain, the higher the latency and the more failure points. For critical operations (Build Chain → Test Chain) keep it to 2–3 nodes.
