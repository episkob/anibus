Прокси и цепочки

Visual Chain Builder, ротация, ACTIVE CHAIN-карта и multi-protocol chain — единая прокси-подсистема Anibus 2.2.0.

Обзор

Сервис ProxyChainService + панель Proxy в главном окне. Все HTTP-запросы Anibus, кроме явных loopback-проб, проходят через установленную цепочку. Тип каждого узла:

  • HTTP / HTTPS — стандартный CONNECT-tunnel.
  • SOCKS4 / SOCKS5 — поддерживается аутентификация username/password.
  • TOR — через локальный SOCKS5 порт TOR-демона.

Visual Proxy Chain Manager NEW

Кнопка Build Chain открывает диалог с drag-and-drop редактором:

  1. Слева — пул узлов (импортируется из файла или вводится вручную).
  2. В центре — последовательная цепочка. Узлы можно тянуть/менять местами/удалять.
  3. Справа — параметры выбранного узла: host, port, username, password, тип.
  4. Кнопка Test Chain запускает probe-цепочку (HEAD на тестовый URL).

После применения цепочка отображается в карточке ACTIVE CHAIN на вкладке Proxy:

ACTIVE CHAIN
[HTTPS] corp-gw.local:8443  →  [SOCKS5] tor-bridge:9050  →  TARGET

Ротация и chain-режимы

  • Strict chain — все узлы используются в указанном порядке.
  • Round-robin — каждый запрос идёт через следующий узел в цепочке.
  • Random — случайный узел на каждый запрос.
  • Fallback — первый рабочий узел при ошибке вышестоящего.

Локализованный диалог

Тексты Proxy Chain Builder локализованы на EN/IT/RU. Все ключи валидируются ResourceBundleValidationTest — добавление новой строки требует трёх переводов одновременно.

Timeout-профили

HttpClientFactory.TimeoutProfile:

ПрофильConnect / ReadГде применяется
FAST2 / 2 сMassive port probes, favicon
NORMAL5 / 5 сStandard HTTP проба
SLOW10 / 10 сAuth-сервисы, IdP
VERY_SLOW20–30 сOAuth token-endpoint, RDAP, AXFR

Профили подаются вторым аргументом в HttpClientFactory.open(url, profile). Через прокси-цепочку проходят все вызовы этого фасада.

Retry-политика

Экспоненциальный backoff + jitter для временных сетевых ошибок (timeout, reset, 5xx). Конфигурируется в Config → Network → Retry:

  • Max attempts (по умолчанию 3).
  • Base delay (250 ms) с экспонентой 2.
  • Jitter ±25% для размазывания нагрузки.

Trust-all SSL

InsecureSsl — единая утилита trust-all SSLSocketFactory + hostname-verifier. Используется детекторами, которым нужно работать с самоподписанными сертификатами (KeycloakDetector, IdentityProviderDetector, SqlMetadataExtractor). Применяется только внутри сканера, не подменяет глобальный TrustManager JVM.

Безопасность Чем длиннее цепочка, тем больше latency и точек отказа. Для критичных операций (Build Chain → Test Chain) используйте 2–3 узла.
