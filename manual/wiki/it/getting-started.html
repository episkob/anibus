Installazione e avvio

Il percorso minimo da un sistema pulito alla prima scansione in Anibus 2.2.0.

Requisiti di sistema

ComponenteMinimoNote
SOLinux x64 / macOS / Windows 10+Testato su Linux (Fedora/Ubuntu). Su Wayland — senza particolarità.
JDKJava 21 (LTS)Richiesto il supporto ai virtual thread (JEP 444), nessun flag di preview necessario.
JavaFX21.0.5Inclusa come dipendenza Maven, non serve installarla a parte.
Maven3.9+Nel progetto è presente ./mvnw, è possibile usarlo.
RAM1 GBPer scansioni batch di 100+ target sono consigliati 2 GB o più.
PermessiUtente normalePer scansioni UDP di alcuni servizi può servire root/CAP_NET_RAW.

Build dai sorgenti

git clone <repo> anibus-desktop
cd anibus-desktop
./mvnw -B -DskipTests package
./mvnw -B -Pjavafx javafx:run

Gli artefatti dopo la build si trovano in target/. I test (162 in totale, 50+ classi) si avviano con:

./mvnw -B test

Esecuzione di un singolo test:

./mvnw -B test -Dtest=SQLInjectionAnalyzerTest

Primo avvio

  1. La finestra si apre in tema scuro (Bootstrap 5 Dark, CSS personalizzato).
  2. Nel titolo della finestra — la versione Anibus Desktop 2.2.0.
  3. Parte sinistra — campo Target e gruppo dei pulsanti di scansione.
  4. Centro — console Scan Results con timestamp realtime e filtro (Ctrl+F).
  5. Menu superiore — configurazione, tema, dizionari, proxy, scheduler, esportazione.
Suggerimento Al primo avvio apri Config → Tema e seleziona Scuro o Chiaro. Il tema chiaro è un override CSS anibus-style-light.css.

Struttura delle directory utente

PercorsoScopo
~/.anibus/history/Salvataggio automatico dei risultati delle scansioni (vedi Cronologia scansioni).
~/.anibus/cve-cache/Cache offline CVE/EPSS/KEV (vedi CVE Offline DB).
~/.anibus/wordlists/Dizionari utente (Subdomain / SQLi payloads / Endpoints).
~/.anibus/banner-timeline/Store TSV per la Port Banner Timeline.

Panoramica dell'interfaccia

Finestra principale

  • Target — IPv4/IPv6/hostname/URL; le parentesi quadre in IPv6 vengono rimosse automaticamente.
  • Scan Results — console con gruppi CRITICAL/HIGH/MEDIUM/LOW. Menu contestuale → cronologia, diff, SQL extraction.
  • Pulsanti a sinistra — Scan, UDP, Subdomain, Source Map, ParamMiner, Diff Mode, Scheduler Start/Stop, ecc. Dettagli nelle Scansioni di base.
  • Status bar — indicatori dei dizionari attivi, della catena proxy e dello stato dello scheduler.

Menu

  • Config — tema, lingua, dizionari, profili di timeout.
  • Discovery — Auth Crawling, Passive Recon, dialoghi GraphQL/JWT/CORS, import batch.
  • Proxy — Build Chain, ACTIVE CHAIN, rotazione.
  • Scheduler — pianificazioni, drift baseline.
  • Export — PDF, HTML, JSON, TXT.

Localizzazione

Tutte le stringhe UI sono raccolte in tre bundle: Messages_en, Messages_it, Messages_ru. La sincronia delle chiavi è verificata dal test JUnit ResourceBundleValidationTest. Il locale è determinato dal sistema e si può cambiare esplicitamente in Config → Lingua.

Cosa fare dopo

  • Avvia la prima scansione su un qualsiasi target pubblicamente autorizzato (scanme.nmap.org o un tuo lab).
  • Studia le catene proxy se scansioni attraverso un gateway aziendale.
  • Abilita la cache offline CVE se lavori in ambienti air-gapped.
